اگر تا امروز فایل‌هایی مثل «گزارش-نهایی.docx»، «گزارش-نهایی-ویرایش۲.docx» و «گزارش-نهایی-واقعا-نهایی.docx» ساخته‌اید، مشکلی که Git حل می‌کند را از قبل تجربه کرده‌اید — فقط برای کد.

## Git چیست؟

Git یک سیستم کنترل نسخه (Version Control System) است که تاریخچه‌ی کامل تغییرات یک پروژه را ثبت می‌کند: چه کسی، چه زمانی، چه چیزی را تغییر داده. برخلاف ساختن فایل‌های تکراری با نام‌های مختلف، Git هر تغییر را به‌صورت یک «commit» ثبت می‌کند و همیشه امکان بازگشت به هر نسخه‌ی قبلی وجود دارد.

## چرا فقط ذخیره‌کردن فایل کافی نیست؟

در کار تیمی، چند نفر همزمان روی یک پروژه کار می‌کنند. بدون ابزاری مثل Git:

- تغییرات افراد مختلف به‌راحتی روی هم بازنویسی می‌شود.
- هیچ تاریخچه‌ی مشخصی از اینکه «چرا این تغییر انجام شد» وجود ندارد.
- بازگشت به نسخه‌ی قبل از یک باگ، تقریباً غیرممکن است.

Git این مسائل را با مفهوم «شاخه» (branch) و «ادغام» (merge) حل می‌کند: هرکس می‌تواند روی نسخه‌ی جداگانه‌ی خودش کار کند و در نهایت تغییرات به‌صورت کنترل‌شده با هم ترکیب شوند.

## تفاوت Git و GitHub

این دو اغلب اشتباه گرفته می‌شوند:

- **Git** یک ابزار نرم‌افزاری است که روی کامپیوتر شما اجرا می‌شود و تاریخچه‌ی تغییرات را مدیریت می‌کند.
- **GitHub** (یا مشابه‌هایی مثل GitLab) یک سرویس آنلاین است که پروژه‌های Git را میزبانی می‌کند تا تیم‌ها بتوانند از راه دور با هم همکاری کنند.

به بیان ساده: Git ابزار است، GitHub جایی است که نتیجه‌ی کار با آن ابزار را نگه‌داری و به‌اشتراک می‌گذارید.

## دستورهای پایه‌ای که باید بشناسید

```bash
git init                     # شروع یک پروژه جدید Git
git add file.txt              # آماده‌سازی فایل برای ثبت تغییر
git commit -m "توضیح تغییر"   # ثبت تغییر با یک پیام توضیحی
git push                      # ارسال تغییرات به سرور (مثل GitHub)
git pull                      # دریافت آخرین تغییرات از سرور
```

## یک عادت خوب: پیام‌های commit معنادار

یکی از رایج‌ترین اشتباهات مبتدی‌ها، نوشتن پیام‌هایی مثل «تغییرات» یا «fix» برای هر commit است. یک پیام خوب، دقیقاً توضیح می‌دهد «چرا» این تغییر انجام شده، نه فقط «چه چیزی» تغییر کرده — این عادت ساده، ماه‌ها بعد که به تاریخچه‌ی پروژه نگاه می‌کنید، ارزش خودش را نشان می‌دهد.

## جمع‌بندی

Git فقط ابزار «برنامه‌نویس‌های حرفه‌ای» نیست؛ برای هر پروژه‌ای که بیش از یک نفر روی آن کار می‌کند یا نیاز به تاریخچه‌ی قابل‌اعتماد دارد، ضروری است. یادگیری چند دستور پایه‌ای آن، یکی از باارزش‌ترین مهارت‌هایی است که می‌توانید در همان روزهای اول یادگیری برنامه‌نویسی کسب کنید.
